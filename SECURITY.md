# Security Policy

## Development data

Use dummy records during development. Do not commit real student, guardian, examination, attendance or private staff information.

## Secrets

Do not commit `.env`, `.env.local`, API keys, service-role keys, passwords or database credentials.

## Public content

Only approved school information and authorised photographs should be published.

## Private modules

Private student and academic modules require authentication, role-based access control, audit logging, secure backups and formal approval before real data is introduced.

## Reporting

Security issues should be reported privately to the authorised school coordinator and project maintainer.
